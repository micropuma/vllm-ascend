### 分析与结论

1. **FlashComm1 单独启用基本没有可见收益。** `qwen_flashcomm1` 的持续输出吞吐仅比 baseline 高 0.4%，Mean TTFT 低 1.7%，其余平均与 P99 指标的差异均在约 1%--2% 内。这更接近单次 benchmark 的自然波动，不能据此宣称 FC1 单独加速了 Qwen TP。

2. **DBO 单独启用在该负载下明确退化。** 输出吞吐下降 10.2%，Mean TTFT、TPOT、ITL 和 E2E 分别增加 5.7%、11.7%、11.7% 和 9.3%。尤其 P99 TPOT 从 879.21 ms 升至 1223.63 ms（+39.2%），表明该配置的 decode 尾部存在额外阻塞或调度抖动；这不是只影响 prefill 的退化。

3. **DBO + FlashComm1 呈现强协同，而非两个单项收益的简单相加。** 若无交互，按单项观测结果估计，组合输出吞吐应约为 66.8 tok/s（baseline 74.04，加上 FC1 的 +0.4% 与 DBO 的 -10.2%）；实际为 99.50 tok/s，比该无交互预期高约 32.7 tok/s（+44.3 个百分点）。组合将测试总时长缩短 27.65 s，并让请求吞吐、输出吞吐、总吞吐同步提高约 34%，说明收益覆盖了本次长 prefill 主导的端到端服务流程，而非仅某个统计口径。

4. **组合配置改善同时覆盖 prefill、decode 和尾延迟。** Mean/P99 TTFT 分别下降 26.2%/24.8%，Mean/P99 TPOT 下降 25.5%/26.1%，Mean/P99 E2E 下降 25.8%/25.4%。中位数指标也一致下降约 26%，没有以牺牲尾延迟换取平均吞吐的迹象。

5. **不要用 Peak output throughput 判断本次优化。** 最优组合的瞬时峰值为 340 tok/s，低于 baseline 的 550 tok/s，但其持续输出吞吐为 99.50 tok/s，高于 baseline 34.5%。峰值是短时间窗口统计，易受请求到达、warmup 和批次边界影响；在固定总 token 的压测中，应以 benchmark duration、持续吞吐以及 TTFT/TPOT/E2E 为主。

6. **因果归因仍需 profiler 证据。** 这组 2×2 A/B 足以证明二者在该 workload 中存在正向交互，但不能仅凭服务侧结果定位到具体通信算子或 stream 排程。下一步应对 baseline、DBO 和 DBO+FC1 分别采集非性能宣称用途的 Ascend profiler trace，量化 `Comm(exposed)`、`Overlapped`、free/idle 比例，并检查 DBO record/wait 是否使 TP 通信与 FC1 改善后的计算段形成更好的时长匹配。

### 复现与验证建议

- 固化四组启动命令、TP size、rank mapping、精度、CANN/driver/torch_npu/vLLM-Ascend commit、环境变量和随机种子；每组至少重复 3 次，报告均值与标准差/置信区间。
- 在同一环境补充 profile 模式 trace；profile 开销下的时延仅用于诊断，正式性能结论继续使用 plain benchmark。
- 对 `qwen_dbo_fc1` 做输出一致性或约定精度门限验证，再将其作为可合入的性能结论；同时复核 DBO-only 的 P99 TPOT 抖动来源（stream wait、host gap、通信暴露或负载不均衡）。

### 结论

1. **Qwen3-30B TP 的最优已验证组合是 `dbo_fc1`**：持续输出吞吐 +34.5%，Mean TTFT -26.2%，Mean TPOT -25.5%，Mean E2E -25.8%；所有成功请求完成，且中位数和 P99 同向改善。
2. **Qwen 的收益来自 DBO 与 FlashComm1 的协同**：FlashComm1 单独仅 +0.4% 吞吐，DBO 单独为 -10.2%；不能将组合的 +34.5% 归因于任一开关。需要 profiler 量化通信暴露和双流重叠，定位这一交互的机制。
3. **dbo_fc1 是 DeepSeek TP 最优组合**：+25.8% 吞吐提升，DBO 与 FlashComm1 在该场景也表现出互补性。
4. **DBO 的收益取决于模型与负载**：DeepSeek DP/TP 取得正收益，但 Qwen TP 的 DBO-only 退化，并在 decode P99 TPOT 上出现明显抖动；小批次场景同样不适合无条件开启 DBO。
5. **后续决策应以持续吞吐与分位延迟为准**：Qwen 最优组合的瞬时 peak output 低于 baseline，不能把该短窗口指标当作优化成败依据。
6. **进入性能结论前仍需重复性和质量门禁**：固定完整环境后至少三次 plain benchmark，并补充 DBO+FC1 的输出精度验证和 profiler 诊断；profile 数据不用于最终时延宣称。
